tieout

Independently-verifiable reconciliation for an onchain wstETH position.

Source on GitHub ↗

tieout rebuilds an onchain wstETH position — a token representing staked ETH — from public blockchain data alone, checks it against an accounting ledger, and produces a report that anyone holding the same ledger file can reproduce byte-for-byte. It’s built for compliance and audit people who need verification that doesn’t rest on trusting the reporter. This page demonstrates the pipeline end-to-end: a position read live from mainnet, two demo reconciliations, and a tamper-evidence anchor read live from Base.

    Reproduce it yourself · the auditor’s path

    Don’t take this page’s word for it. One command re-downloads the public chain data, rebuilds the reconciliation, and must reproduce the slice report’s exact hash — on your machine, without trusting this page or the report’s author. 

    git clone https://github.com/nick-railsback/tieout && cd tieout
pnpm install && pnpm -r build
ETH_RPC_URL=<mainnet-archive-rpc-url> \
  pnpm --filter @tieout/recon verify \
  fixtures/slice/report.json fixtures/slice/ledger.json

    Prereqs: Node 24 and pnpm (corepack enable). Needs a mainnet archive RPC — a provider that can answer “what was the state at block X” for old blocks; free tiers include this. Exit code 0 means byte-identical reproduction; any failure is a clean one-line typed error. Full walkthrough in the README ↗.

    Where this goes next

    The natural expansion directions are continuous monitoring, multiple addresses, and more asset types. A second set is deliberately not built — wallet connect, client-side report generation, in-browser verify, downloadable reports, address lookup. Some are parked on plain scope discipline; the rest would have tieout act on a visitor’s behalf, making it a trusted intermediary — the exact role it exists to eliminate.
